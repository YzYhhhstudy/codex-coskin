# CoSkin 工程笔记（总结与经验）

> 2026-07-18，v0.1 → v0.7 一天迭代出来的经验。给未来的自己和贡献者。
> 同目录还有：[codex-token-inventory.json](codex-token-inventory.json)（真机 token 清单）、[theme-prompts.md](theme-prompts.md)（提示词库）。

## 架构一句话

不是「往界面糊壁纸」，而是**把几个种子色编译成对 Codex 官方三族变量
（`--color-token-*` / `--color-*` / `--vscode-*`，约 110 个）的覆写**，让所有控件自动跟随；
结构层只做壁纸、玻璃面、装饰（品牌行/标题板/桌宠）和可读性兜底。
核心函数全部**自包含**，Node 端直接调用、页面端 `toString()` 内嵌——一份实现两端跑，杜绝逻辑漂移。

## 踩过的坑（每条都付过学费）

1. **`[data-vscode-context]` 包的是整个会话视图，不是编辑器。** 给它设不透明底会把壁纸整块挡死。
   代码可读性应由 `pre` 底色 + 编辑器/终端自绘的 `--vscode-*` 背景保证。
2. **负 z-index 的绘制顺序**：stacking context 内，负 z 子元素画在「普通流块级背景」**之下**。
   想让垫底板画在容器背景之上、文字之下，必须让宿主列自成堆叠上下文（`isolation: isolate`）。
3. **写进官方 DOM 的每一笔都要记账**：我们给标题列写过 `position/isolation` 内联样式，
   还原时必须按 `data-csPrev*` 记录逐笔恢复——「还原即原样」是可以被断言的契约，不是口号。
4. **雾纱不能焊死在图片管线里**：薄纱/幕布必须是按可见度档位编译的独立层，
   否则「原图」档永远做不出来。用户传自己的图，默认期望是看到原图。
5. **深浅判定要有「纸色守卫」**：浅底大墨块的图会把均值亮度拖过线。主色饱和度低且不暗 → 按纸面处理；
   再给面板留手动翻转，算法永远要有逃生门。
6. **官方外观开关是 `html.electron-light/dark`**：随主题同步翻转可根治代码高亮错配；还原时要恢复原类。
7. **阅读面板（Review/文档）是背景全透明的 CodeMirror**（`.cm-editor`）：文字不能浮在壁纸上，
   给它不透明特权，滚动忽糊忽清的观感问题随之消失。
8. **真机诊断三板斧**（全部只读，不打扰使用者）：
   `elementsFromPoint` 中心点堆栈找遮挡层；`getComputedStyle` 枚举自定义属性挖 token；
   按工具类名（`bg-token-X` → `--color-token-X`）反推变量并读值。
9. **绝不静默重启用户在用的应用**：检测到运行中必须当面征得同意（confirmRestart 门）。
10. **注入脚本模板里的正则反斜杠必须双写**：buildInjectionScript 的页面代码写在 JS 模板字面量里，
    `\(` 会被煮成 `(`（正则从字面括号变成分组），页面端静默匹配失败而 Node 端自测全绿。
    凡在模板内写正则：`\\(`；或改用 toString() 内嵌的自包含函数（不经模板煮）。
11. **模拟页验证 ≠ 真机**：mock 能锁住回归（45 项断言、还原逐项回基线），但真机 DOM 总有惊喜
    （见坑 1、7）。每次真机反馈都应转化为 mock 的新结构 + 新断言。

## 已知待办（2026-07-18 审查遗留）

来自多智能体对抗审查（4 维度 × 2 怀疑者），**已修**：还原时标题列内联样式残留（坑 3）。

**双确认、未修**：
- RESTORE 后 `window.__coskinSetTheme` / `__coskinQuickFromDataUrl` / `__coskinState` 闭包仍存活：
  ① 在途图片上传落定会「复活」皮肤（还原后 1-2 秒竞态窗口）；② 闭包持有含 base64 壁纸的
  THEMES，每窗口滞留数 MB。修法：RESTORE 里 delete 三个全局 + 注入代际标记拒绝过期回调。

**单票存疑（下轮验证）**：
- 多窗口 apply/restore 的部分失败被静默吞掉（failed 计数无人消费），成功提示可能误导；
- `apply --spec` 的 wallpaper 分支只查扩展名不查 8MB/空文件，坏主题会先落盘再每次应用必炸。
